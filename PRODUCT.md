# Split Studio

<!-- impeccable:product-schema 1 -->

## Platform
web

## Stack
Confirmed by the user: standalone React + TypeScript project, SDDS FinAI and Node.js backend.

## Users
Analysts assemble and maintain entity detail cards without writing JSON or frontend code.

## Product Purpose
Create Split-view definitions through a visual constructor and resolve them on the backend. The same renderer displays the preview and the running application.

## Capabilities and Constraints
Phase one is read-only: shell, header, status, tabs, field groups, collapsible sections, text, links and related-record tables. The user clarified that separate microfrontends are widgets. Their host integration must be explicit and independent of the SDUI tree. Forms and comments are future scope. No real enterprise API, authentication provider or production deployment was provided.

## Brand Commitments
Use SDDS FinAI and the 17 supplied Split-view documentation and application screenshots. Preserve their calm enterprise layout and existing terminology. Content examples are synthetic.

## Product Principles
Semantic blocks instead of pixel placement. Arbitrary API paths or literal values, with catalog suggestions and typed editors. Host-registered microfrontends receive declarative parameters and locally created callbacks. Contextual guidance and useful defaults. Stable IDs preserve local reading state. Published definitions are immutable revisions.
