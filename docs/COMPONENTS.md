# Параметры компонентов и полей

В конструкторе выберите блок или конкретное поле и откройте **«Параметры компонента»** либо **«Оформление и формат поля»**. Доступные настройки определяются контрактом этого типа. Их можно редактировать и через JSON.

`props` содержит источники значений, а не произвольные свойства React. Например:

```json
{
  "showTitle": { "kind": "literal", "value": false },
  "emptyText": { "kind": "literal", "value": "Записей пока нет" },
  "columns": { "kind": "binding", "path": "presentation.columns" }
}
```

- `literal` задаёт значение в схеме: текст, число, логическое значение или разрешённую контрактом структуру JSON.
- `binding` читает значение из данных API по пути через точку. Путь не вычисляет выражения и не выполняет код.
- Явно заданный `props` имеет приоритет над прежней настройкой блока. Если параметр не добавлен, сохраняется прежнее поведение.
- Значения по умолчанию в списке настроек служат подсказками при добавлении параметра. Они не заполняют отсутствующие данные API автоматически.

Неизвестные параметры, функции, обработчики JavaScript, произвольные CSS и служебные пути вроде `constructor` через `props` передавать нельзя. Актуальный перечень находится в `shared/component-props.ts` и отображается самим конструктором.

## Формат и оформление поля

У поля сохраняются `label`, `source`/`binding` и `format`. Дополнительные настройки находятся в его собственном `props`, независимо от настроек блока.

```json
{
  "id": "expense-amount",
  "label": "Сумма",
  "binding": "entity.amount",
  "format": "money",
  "props": {
    "currency": { "kind": "binding", "path": "entity.currencyLetterCode" },
    "maxFractionDigits": { "kind": "literal", "value": 2 },
    "emptyText": { "kind": "literal", "value": "Сумма не указана" },
    "align": { "kind": "literal", "value": "end" },
    "span": { "kind": "literal", "value": 2 }
  }
}
```

Для данных `{"entity":{"amount":300,"currencyLetterCode":"EUR"}}` поле использует EUR. Валюта не определяется по названию поля. Прежний формат `money` без параметра валюты сохраняет RUB для совместимости.

| Настройка | Допустимые значения |
| --- | --- |
| `label`, `emptyText`, `suffix` | Текст; `label` должен быть непустым |
| `currency` | Трёхбуквенный код заглавными латинскими буквами, например `EUR` |
| `minFractionDigits`, `maxFractionDigits` | Целые числа 0–20; минимум не больше максимума |
| `locale` | Языковой тег Intl, например `ru-RU` |
| `dateStyle`, `timeStyle` | `full`, `long`, `medium`, `short` |
| `timeZone` | Часовой пояс Intl, например `Europe/Moscow` или `UTC` |
| `statusView` | `default`, `accent`, `positive`, `warning`, `negative`, `dark`, `light` |
| `align` | `start`, `center`, `end` |
| `span` | 1, 2 или 3 колонки; ширина ограничена сеткой и адаптируется к узкому сплиту |

В повторяющемся списке пути поля читаются относительно текущей строки. Для доступа к данным всей карточки используйте зарезервированный `$root`:

```json
{
  "currency": { "kind": "binding", "path": "currencyLetterCode" },
  "suffix": { "kind": "binding", "path": "$root.entity.amountNote" }
}
```

Первый параметр берёт валюту из строки, второй — пояснение из карточки. `$root` задаётся рендерером; одноимённое свойство строки его не подменяет.

## Прогресс из данных API

Значение и максимум могут приходить независимо. При `completed: 50` и `total: 200` будет показано 25%.

```json
{
  "id": "completion",
  "type": "progress",
  "title": "Выполнение",
  "value": { "kind": "binding", "path": "entity.completed" },
  "max": 100,
  "showValue": true,
  "props": {
    "max": { "kind": "binding", "path": "entity.total" },
    "view": { "kind": "literal", "value": "positive" },
    "caption": { "kind": "literal", "value": "Обработано задач" }
  }
}
```

`max` на верхнем уровне оставляет совместимый статический вариант. Настройка `props.max` переопределяет его после получения данных. Неположительный максимум или значение за его пределами показывают ошибку.

## Оформление раздела

Раздел поддерживает `plain` — без линии, `divider` — разделитель между соседними блоками и `outlined` — рамка вокруг всего раздела. Без явной настройки сохраняется `divider`.

```json
{
  "id": "contract-details",
  "type": "section",
  "title": "Договор",
  "collapsible": true,
  "defaultOpen": true,
  "props": {
    "appearance": { "kind": "binding", "path": "presentation.sectionAppearance" },
    "size": { "kind": "literal", "value": "m" }
  },
  "children": []
}
```

Здесь API должен вернуть, например, `{"presentation":{"sectionAppearance":"outlined"}}`. Рамка является оформлением SDUI-раздела; установленный Accordion использует свои поддерживаемые виды `clear` и `default`.

## Кнопки и меню действий

У действий шапки, нижнего меню, документов и отдельных кнопок футера есть `presentation`: подпись `label`, доступность `disabled`, отображение `visible`, размер `size` (`sm` / `md`) и вариант `variant` (`primary` / `secondary` / `ghost` / `danger`). Каждый параметр задаётся через `literal` или `binding`. Например, `"disabled": {"kind":"binding","path":"permissions.cannotApprove"}`. Эти настройки доступны в свойствах действия. Параметры микрофронта по-прежнему передаются отдельно в `props`.

## Перенос и выбор элементов

За ручку можно переносить блоки и отдельные поля в дереве и предпросмотре. Space начинает перенос, стрелки выбирают место, Space / Enter завершают, Escape отменяет. Ctrl/Cmd+Z отменяет изменение конструктора. Размер исходного элемента сохраняется, а зоны вставки не меняют высоту карточки. Клик по заголовку раздела в дереве раскрывает или сворачивает вложенные элементы.

Поля шапки и обычных групп используют общие данные карточки и могут переноситься между ними. Поля списка читают текущую строку, поэтому переставляются только внутри своего списка. Для другого списка добавьте поле и явно задайте его источник. Это предотвращает потерю значения из-за незаметной смены области данных.

## Проверки и подключение виджетов

При редактировании схемы проверяются имена параметров, структура источников, типы заданных значений, диапазоны и допустимые варианты UI kit. Привязки дополнительно проверяются после получения данных. Ошибка указывает блок, поле, параметр и, для списков, конкретную строку. Неверный путь или неподходящий тип не заменяются придуманным значением.

У микрофронтов отдельный контракт: `WidgetDescriptor.inputs` определяет известные типы и обязательные параметры. Например, история Taskman требует непустой `flowId`. Необязательные дополнительные параметры по-прежнему могут передаваться по договорённости с хостом. События описываются декларативно в `events`, а функции создаёт доверенный фронтовый адаптер.

ERP-таблица передаёт адрес и параметры настоящему `ErpTableWidget`. Демо API предоставляет данные и метаданные, но не заменяет приватный компонент таблицей из другого UI kit. Подробности подключения: [ERP-TABLE.md](ERP-TABLE.md).
