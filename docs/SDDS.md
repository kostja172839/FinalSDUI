# SDDS FinAI и MCP

Проект использует пакеты, зафиксированные в `package.json`:

| Пакет | Версия |
| --- | --- |
| `@salutejs/sdds-finai` | `0.369.0` |
| `@sddsjs/sdds_finai` | `0.2.3` |
| `styled-components` | `5.3.11` |
| React / React DOM | Диапазон `^18.3.1`; точное разрешение фиксирует lockfile. |

Официальные источники: [документация FinAI](https://plasma.sberdevices.ru/sdds-finai/), [Storybook](https://plasma.sberdevices.ru/sdds-finai-storybook/?path=/story/), [репозиторий Plasma](https://github.com/salute-developers/plasma).

## Роль UI kit

SDUI-контракт описывает смысл блока: группу полей, текст, вкладку, раздел или таблицу. Привязка этого смысла к FinAI остаётся в renderer и его адаптерах. Например, `status` в контракте обозначает статус сущности, а не требование передать определённый набор props в `Badge`.

Собственные композиции оболочки сплита, группы полей и текстового блока реализуют правила из предоставленных макетов. Публичная документация подтверждает `Drawer` и `Sheet`, но в просмотренном каталоге готовый `SplitView` не найден. Resize, переход к fullscreen, ограничения ширины, закреплённые зоны и раскладка поля «подпись — значение» являются поведением нашего приложения.

## Что фактически используется в исходниках

| Элемент интерфейса | Реализация |
| --- | --- |
| Кнопки и иконочные кнопки | `Button` FinAI через адаптеры `Button`/`IconButton` в `src/ui.tsx`. Иконки — `lucide-react`. |
| Поля настройки | `TextField` FinAI через `Input`; `Switch` FinAI через `Toggle`. |
| Выбор из списка | Нативный `<select>` в адаптере `Select`, стилизованный приложением. Это пока не `Select` FinAI. |
| Статус | Прямое использование `Badge` FinAI в `FormattedValue`. |
| Вкладки | Прямое использование `Tabs` и `TabItem` FinAI. |
| Сворачиваемый раздел | Прямое использование `Accordion` и `AccordionItem` FinAI. |
| Связанные записи | `Table` FinAI; поиск, сортировка и пагинация реализованы вокруг него в `ReadOnlyTable`. |
| Оболочка сплита | Собственный `SplitView` и CSS, без использования `Drawer`/`Sheet`. `SplitShell` — архитектурное название этой композиции, отдельного экспортируемого компонента с таким именем нет. |
| Группа полей, текст, аватар ответственного | Собственная семантическая раскладка и CSS в renderer; они не заявлены как готовые FinAI-компоненты. |
| Provider и тема | `PopupProvider` в `src/main.tsx`; CSS-тема `sdds_finai_default__light` из пакета токенов. |

Этот mapping подтверждает использование UI kit в прототипе, но не обещает буквальное совпадение всех состояний с Figma-макетами. Typography и каждая отдельная композиция не были механически перенесены из Storybook.

## Что подтверждено официальной документацией

| Элемент | Источник | Подтверждённая роль |
| --- | --- | --- |
| Drawer | [Документация](https://plasma.sberdevices.ru/sdds-finai/components/drawer/) | Область в окне или frame; модальное и немодальное отображение; header/content/footer; требуется `PopupProvider`. |
| Sheet | [Документация](https://plasma.sberdevices.ru/sdds-finai/components/sheet/) | Содержимое, header/footer, их закрепление, overlay. |
| Accordion | [Документация](https://plasma.sberdevices.ru/sdds-finai/components/accordion/) | Сворачиваемое содержимое; controlled-режим и один активный раздел. |
| Table | [Документация](https://plasma.sberdevices.ru/sdds-finai/components/table/) | Табличное представление, колонки, сортировка, фильтры, resize и настройка ячеек. |
| Поля форм | [React Hook Form](https://plasma.sberdevices.ru/sdds-finai/form/react-hook-form/) | Документирована интеграция с form state; сами формы находятся вне phase one. |

Документация изменяется независимо от текущего приложения. Перед использованием конкретного props нужно сверять его с установленной версией и её TypeScript-типами. Наличие функции у Table не означает, что она уже реализована в SDUI-контракте: например, в первой версии используются снимок данных и клиентская пагинация.

## Темы и токены

Официальное [введение](https://plasma.sberdevices.ru/sdds-finai/) описывает варианты на styled-components, предсобранном CSS и emotion, а также темы и токены из `@sddsjs/sdds_finai`. В этом проекте выбран вариант на styled-components.

Тему следует подключать на уровне приложения. Аналитик настраивает смысл и ограниченные варианты интерфейса; технические имена CSS-переменных, произвольные цвета и пиксельные координаты не входят в редактор шаблона.

## MCP для справочной работы

Есть [официальная инструкция именно для FinAI](https://plasma.sberdevices.ru/sdds-finai/how-to-mcp/). MCP работает через `stdio` и предоставляет документацию, свойства компонентов, примеры и гайды.

Команда для версии этого проекта:

```text
npx -y @salutejs/sdds-mcp@latest --lib sdds-finai --version 0.369.0
```

Пример конфигурации MCP-клиента:

```json
{
  "mcpServers": {
    "sdds-finai": {
      "command": "npx",
      "args": [
        "-y",
        "@salutejs/sdds-mcp@latest",
        "--lib",
        "sdds-finai",
        "--version",
        "0.369.0"
      ]
    }
  }
}
```

Это пример в документации, а не изменение конфигурации компьютера пользователя. Набор tools зависит от MCP-клиента; официально перечислены `list_components`, `get_component`, `get_component_props`, `get_component_examples`, `get_tokens`, `get_installation_guide`, `get_form_guide` и другие справочные инструменты.

В официальном описании указаны версии FinAI начиная с `0.334.0` и автоматический переход на `latest`, если запрошенная версия не найдена. Поэтому перед использованием ответа нужно проверить, какой версии он соответствует. Совпадение команды с рекомендуемым форматом не подтверждает наличие документации для каждого релиза на сервере.

При подготовке прототипа официальные страницы были изучены через web. MCP через toolkit этой сессии не подключался и его инструменты не вызывались. Проверять работу настроенного MCP-клиента нужно отдельно.
