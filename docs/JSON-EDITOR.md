# JSON, проверка значений и новые компоненты

В конструкторе поле и его тестовые данные настраиваются вместе: выберите компонент, укажите путь в данных и задайте «Значение в предпросмотре». Кнопка «Добавить значение в данные» создаёт отсутствующий путь. Привязка поля остаётся в шаблоне, а введённое значение записывается в данные предпросмотра. Подсказки путей включают ключи текущего ответа API.

Кнопка **«Данные и шаблон»** над сплитом открывает в конструкторе два JSON-редактора одновременно. Общий черновик синхронизируется с визуальными свойствами; редактор и сплит располагаются рядом на широком экране и друг под другом на узком. Открытие панели сохраняет экземпляр карточки, активную вкладку и состояние чтения. При временно некорректной настройке остаётся последняя корректная карточка с сообщением.

Кнопка **JSON** в верхней навигации также сохраняет отдельный широкий режим для работы с кодом.

В широком режиме «Тестовые данные» — ответ API для предпросмотра, «Шаблон карточки» — определение компонентов. Это те же буферы, которые доступны в конструкторе. Примените каждый изменённый буфер либо сбросьте его перед сохранением и публикацией. Переключение режима сохраняет неприменённый текст. Данные предпросмотра не записываются в опубликованный шаблон.

Если данные или шаблон изменились визуально, а JSON содержит неприменённые правки, применение старого текста блокируется. Ваш текст сохраняется; доступны копирование и явная загрузка актуальной версии. Такую же защиту имеет тестовое значение поля при изменении того же пути в другом редакторе. Незавершённый JSON и числовой ввод учитываются при блокировке сохранения.

Для колонок таблиц и полей списков тестовое значение относится к первой подходящей строке. Источник списка можно дополнить непосредственно в его свойствах. Пути контекста хоста `$context` и текущей записи `$item` доступны для привязок, но не перезаписываются редактором тестовых данных.

Редактор использует [CodeMirror для React](https://github.com/uiwjs/react-codemirror) и строгий разбор JSON. Есть подсветка, номера строк, сворачивание, поиск, форматирование и перенос длинных строк. Tab переводит фокус к следующему элементу интерфейса. Панель замечаний показывает строку/колонку и путь; нажатие переводит курсор к значению.

Синтаксические ошибки, комментарии, дублирующиеся ключи, опасные служебные свойства, избыточный размер и вложенность блокируют применение. Схема дополнительно проверяется общим валидатором клиента и сервера. ID открытого шаблона нельзя подменить через JSON. Неверные типы и правила значений показаны как замечания: данные можно применить, чтобы увидеть ошибку возле конкретного поля в карточке. Остальные блоки продолжают работать.

В настройках каждого реквизита доступны обязательность, минимальная/максимальная длина текста и числовые границы. Проверяется формат даты, конечность числа и допустимый адрес ссылки. Неверные буквальные значения в самой схеме блокируют публикацию. Правила применяются к реквизитам шапки, группам полей, колонкам таблиц, суммам и полям списков сущностей. Ошибки настроек имеют `aria-invalid` и связанный текст рядом с полем.

Данные примеров называются `entity` (текущий объект) и `collections` (связанные списки). Это соглашение, а не обязательная обёртка для ответов ваших API: произвольные безопасные пути по-прежнему разрешены. Старые `asset.*` и `events` читаются через совместимые aliases; сохранённые публикации не переписываются. В конструкторе используется отдельная проекция старого определения с нейтральными путями.

По новым макетам добавлены блоки:

| Тип | Настройка |
| --- | --- |
| `callout` | Информационное сообщение: источник текста и тон. |
| `metrics` | Суммы/показатели с подписями, форматами, пояснениями и правилами. |
| `recordList` | Список карточек сущностей: заголовок, описание, ссылка и реквизиты относительно каждой строки. |
| `documents` | Документы и связи: название, описание, статус, размер, безопасная ссылка либо зарегистрированный виджет. |

«Пример договора» загружает в текущий черновик синтетический пример всех этих блоков, закреплённых реквизитов шапки и таблицы внутри раздела. Сохранение и публикация выполняются отдельно. Он не реализует бизнес-операцию распределения платежа: её форма может открываться через зарегистрированный микрофронт.
